## 本版可做的业务

能力/版本/启动身份查询，绑定会话，设备状态、心率/呼吸/在床/活动查询与推送，独立保活，实际启停确认，安装目标参数、报告/报警配置及保存，8类事件状态、触发/恢复/未知/结束通知、事件历史补查/确认，以及本轮监护统计。安装设置在下一次START前应用并读回，失败不启用监护。

8类为呼吸低/高、心率低/高、持续无可靠呼吸/心率估计、在床过久、离床未返。旧值保持、低质量和谐波冲突不默认作为新生理异常证据。当前估计量程有限：呼吸12—24次/分，心率频谱48—120次/分；阈值配置不会扩大量程，范围外可能转为无可靠估计。

厂家OTA、评分、医学分期及不存在的传感器能力不伪装成已实现命令；本版是既有RSP业务的双芯片软件闭环，不是厂家5359协议兼容版。

## 烧录与连线

两颗芯片都要更新：雷达V29提供带事务号的实际执行回执和呼吸确认元数据，W803 P1提供产品服务。仅P1配旧V28会拒绝控制，不能跳过雷达更新。烧录方法沿用各自工具：W803 `.fls`走02组与PA0/黄G；雷达 `.img`走01组、黄G保持复位、白F/Y3时序。烧录完成后关闭工具，运行时01组不接电脑TX。

产品口使用现成六针排针的无数字TX/RX：USB串口TXD→六针RX，RXD←六针TX，GND共地，3.3V通信，115200/8N1。02组继续用于日志/烧录。只有一只适配器时，烧录结束后断电换线到六针组，再打开联调工具；不需要新增芯片间飞线。

运行：PA0断地绝缘，Y3松开，先保持白F接地启动W803；联调工具连接后可以看到设备响应，释放白F让雷达启动。等待设备状态和安装读回就绪，点击“开始监护”；看到控制状态“运行中”、监护启用1才算实际开始，不能把发送成功或PENDING当作已执行。结束点击“停止监护”，检查已停止及监护启用0。

## 参数操作

停止后先读取配置，修改后“应用到RAM”。报告/事件参数更新RAM，安装项是下次START前待应用的目标。需要断电保留时点击“保存当前RAM配置至Flash”；恢复默认只改RAM。参数写入W803的NVS新命名空间，不改雷达校准区；不得在监护或雷达实际运行时写配置。

重新上电、重新连接、读取配置，核对revision与内容；开始前会应用已保存的安装目标，再通过“实际安装”读取雷达确认值。源vertical模式不支持或实际读回不一致会拒绝启用监护，不隐瞒为成功。

连接后自动保存原始请求/回复及解析事件至本目录 `logs\P1_COMx_时间.jsonl`。查询正常但数值无效时分别看监护状态、在床、Q/HCON、测量年龄及故障位，不把保活当测量有效。

## 工程文件

`App/product_protocol.c`为不依赖SDK的协议、控制/配置/事件服务；`App/product_runtime.c`绑定UART、源文本与R1快照，所有产品输出仅由产品任务写；`BSP/product_board.c`封装UART1、TRNG和NVS。心率核心仍在原Algorithm目录，文件哈希锁在 `reference/heart-core-lock.json`。

构建：本机Python运行 `tools/ide_build.py`；VS Code中使用原生成任务。P1新增协议任务优先级3，接收4、心率2、日志1；最终性能仍须板测。

软件检查：`tools/build_protocol_native.cmd` 后运行 `tests/test_protocol.py`、`test_mcu_client.py`、`test_storage.py`；`tools/build_runtime_native.cmd` 后运行 `tests/test_runtime.py`。心率回归沿用 `tools/build_native.cmd` 与 `check_native.py`、`check_release.py`。脚本不自动连接COM，不复位、不烧录，不批量删除文件。
