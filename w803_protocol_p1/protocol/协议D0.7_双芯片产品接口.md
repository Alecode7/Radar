# RSP D0.7：双芯片产品接口

日期：2026-11-20。W803固件P1，配套RS6130 V29。延续RSP线版本1.1，能力结构修订2；原D0.6只读ID及结果布局保留，增加业务命令与独占二进制串口。此文是本版交付契约；旧规划中未实现的同名业务不能替代下表。

## 1. 芯片与串口职责

RS6130继续以200ms周期采集，执行原选格、呼吸、在床和活动判断；通过既有板内UART0→W803 UART3发送HRIN、SLEEP和新增BRC/PCTL。W803继续使用R1的double ROTATE16心率核心，并汇总测量、协议控制、配置和事件。

| 端口 | 模块引脚 | 本版用途 |
| --- | --- | --- |
| W803 UART0 | 八针TX02/PB19、RX02/PB20 | 原图形烧录与文本调试，不发送产品二进制 |
| W803 UART1 | 六针TX/J1.2/PB6、RX/J1.5/PB7 | 产品协议，115200、8N1、3.3V逻辑，只有协议任务写入 |
| W803 UART3 | PB0/PB1，板内已连线 | RS6130内部文本链路；外部01组不并接电脑TX |

产品接线：主板TX→六针RX，主板RX←六针TX，公共GND。供电仍按模块原接口，信号电平与电源电压分开。不能将雷达UART1/HIF与这里的W803 UART1混同。

厂家R60ABD1两份本地PDF只作为初始化、查询、功能/波形分层和状态/报告组织的参考。本版不改为5359/SUM/5443厂商帧，也不宣称兼容厂家上位机、OTA、睡眠评分或医学睡眠分期。

## 2. 封装与错误

所有多字节整数显式小端，不能发送C原生结构体。整帧最多256字节，载荷最多240字节。

| 整帧偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | byte[2] | 52 53 |
| 2/3 | u8/u8 | major=1，minor=1 |
| 4 | u8 | 请求1、应答2、主动上报4 |
| 5 | u8 | 保留0 |
| 6 | u16 | 消息ID |
| 8 | u32 | 非0序号；应答与请求相同，主动上报独立计数 |
| 12 | u16 | 载荷字节数 |
| 14 | bytes | 载荷 |
| 最后2字节 | u16 | CRC16/CCITT-FALSE，小端 |

CRC覆盖偏移2至CRC之前，poly=1021、init=FFFF、非反射、xorout=0；`123456789`检查值29B1。错误版本/保留位/长度/CRC丢弃，单字节重同步；残包间隔超过200ms后恢复扫描。CRC与通信token用于检错、隔离迟到包，不是加密认证。

无会话应答载荷为 `result/u16 + detail/u16 + data`。带会话应答增加 `token/u64`，即 `result/u16 + detail/u16 + token/u64 + data`；错误也回显token，不带部分成功体。

| result | 含义 |
| ---: | --- |
| 0 | 请求已接受/读操作成功；控制仍须检查实际状态 |
| 1 | UNSUPPORTED |
| 2 | BAD_LENGTH，detail为期望请求载荷长度 |
| 3 | BAD_ARGUMENT |
| 4 | BUSY，未执行此次业务 |
| 5 | NOT_READY |
| 6 | CONFLICT：同编号不同请求或配置版本不匹配 |
| 7 | STORAGE：保存/读回失败，不能认为已持久化成功 |
| 8 | INTERNAL |
| 9 | SESSION_REQUIRED |
| 10 | OLD_SEQUENCE |
| 12 | BOOT_CHANGED：未绑定正确启动身份，禁止写入 |

## 3. 启动身份、会话与重试

上电从W803硬件TRNG取得非0的64位boot_id。代码核对所用SDK实现为TRNG而非固定种子PRNG；异常/重复读值拒绝建立写会话。随机身份的唯一性是概率性的，尚须多次实板重启验证，不是持久单调计数或密码学认证承诺。

主板流程：GET_CAPS→GET_IDENTITY→取新的非0 token→OPEN(token,boot_id)→CONTROL/HEALTH→按需START→轮询实际控制状态→SNAPSHOT/ALERTS/EVENTS。连接本身不自动启动采样。

每次重连必须换token。会话内请求序号严格递增、非0；一次只保留一个待应答事务。设备缓存最后一次完整请求及回复：相同完整请求重试回相同字节，不重复执行；同序号不同内容CONFLICT，更旧序号OLD_SEQUENCE。控制和保存超时后先查实际状态，不能换新序号盲目重做。序号用尽须换会话。

主板参考800ms重试相同完整帧，最多2次重试；从首次发送起2400ms硬截止，feed与poll都检查迟到应答。断开、boot_id变化、token不匹配时清空结果并重新握手。定时保活不能延长测量年龄，也不能替代状态/结果查询。参考客户端保守加计整个请求事务的经过时间，避免缓存回复在重传后使年龄变年轻；STOP发出即清本地旧结果。

旧8字节OPEN保留为只读会话；新16字节OPEN绑定当前boot_id后才能START/STOP、修改/保存配置、确认事件。OPEN不是监护会话，START确认成功才建立monitor_id。会话token重连不重置监护统计。

### 能力与身份

0100数据：0/1线版本1/1；2/u16结构修订2；4/u32能力0x1FFB；8/u16最大请求载荷240；10/u16最大应答载荷240；12/u16结果ID8101；14/u16结果长度56；16/u32报告周期；20/u32限制0x20；24/u64uptime；32/char[32]固件名。

能力bit0/1基础查询，bit2 HEX诊断（本版0），bit3结果推送，bit4独立保活，bit5会话，bit6设备状态，bit7启动身份，bit8控制，bit9配置，bit10事件，bit11统计，bit12独占二进制串口。限制bit5表示当前估计算法量程有限，配置报警阈值不会扩大量程。

0102数据：0/u64boot_id；8/u64uptime；16/u32capabilities；20/u32faults；24/u16文档修订7；26/u16实现修订1。

OPEN新24字节数据：0/u64uptime；8/u32caps；12/u32restrictions；16/u64boot_id。旧8字节请求返回前16字节。

0112数据沿用D0.6：0/u64uptime；8/u32状态年龄，FFFFFFFF未知；12/u32 flags(bit0曾有SLEEP、bit1当前不可用)；16/u8初始化(1等待雷达、2就绪)；17/u8stage(1等待、6完成)；18/u16保留0。READY不表示在床或心率有效。

### 控制状态32字节

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | u64 | boot_id |
| 8 | u32 | monitor_id |
| 12 | u64 | 内部控制事务operation |
| 20 | u8 | 0停止、1运行、2等待回执、3失败/未确认 |
| 21 | u8 | 雷达最近一次实际运行状态 |
| 22 | u8 | W803监护是否启用 |
| 23 | u8 | 内部action：0停、1启、2查状态、3应用安装设置 |
| 24 | u32 | 雷达返回值的补码；FFFFFFFF表示内部事务超时 |
| 28 | u32 | 设备故障位 |

STOP请求先隔离显示与旧计算，随后等待雷达确认是否停下；失败时不能把“W803已停止使用结果”解释为雷达已停机。重复已确认START不清历史、不重新建立monitor_id；重复STOP不重复执行。STOP可替换等待中的START，其旧回执被忽略。

W803单独重启、雷达继续运行时，不依赖丢失的一次性版本行：周期发送只读PCTL状态查询，以匹配operation、安装读回和CLOCK_OK的有效回执确认兼容源，重新获得控制能力。该过程不自动重开监护；旧V28不支持PCTL，仍不能被当成兼容源。源时钟失效会终止有效监护并清数值，等待重新确认。

内部PCTL每700ms至多发送一次，最多3次，每一阶段3秒未确认标失败。每5秒另查一次实际雷达状态；状态查询不重开监护、不刷新测量。内部事务编号高32位区分本次控制器启动，低32位递增，雷达先经状态查询绑定控制器，再执行启停，缓存最后一次执行回执并拒绝旧编号。

START若发现实际安装参数与RAM目标不一致，会先action3应用并读回，再以新的operation执行action1，两个阶段均须确认。已有雷达运行时不修改安装设置，要求先STOP。action1携带期望安装值，雷达再次核对，防止两阶段之间源重启后用错误几何设置开始。配置阶段失败不启用监护。STOP可以取消待完成的START；已经应用的安装设置不自动回滚，可通过0135读取。

presence/bed/motion：0未知，1否/静，2是/动。sleep_state：0未知、1未在床、2活动、3安静、4疑似睡眠，不是医学分期。flags bit0谐波冲突、bit1活动、bit2状态过期；本版有BRC时间，不再伪造BR年龄。兼容结果体faults保留0，完整设备故障看0123前缀及控制/身份字段。

呼吸BRC只在原算法产生合格的稳定估计时更新源序号和时间；读状态、旧BR保持、无效估计不更新。它是滚动估计的确认时间，不表示检测到一次独立呼吸。跨监护/入床的旧呼吸时间不接纳。心率年龄来自原核心accepted_ms加实际计算延迟；低质量或HCON结果可带标志展示，但不默认作为生理偏高/偏低证据。

停止、离床、输入换代、源重启或SLEEP超过6秒未更新时，结果失效为未知。源输入换代立即清数值与规则确认历史；正常离床保留“曾在床”事实，供离床未返规则使用。主板超过6秒未收到新的0123快照也清本地结果，保活/事件不能续期。

### 8类规则与状态

bit0呼吸低、bit1呼吸高、bit2心率低、bit3心率高、bit4持续无可靠呼吸估计、bit5持续无可靠心率估计、bit6连续在床过久、bit7离床后未返回。

前四类要求当前在床、安静、近期新估计；心率还要求最低Q并按配置排除HCON。触发和恢复均要求配置持续时间及至少2个不同测量序号。旧值保持、重复查询、保活不算新证据。数据过期时进入未知，不解释为恢复；已有活动状态保持锁存，恢复有效观察后重新确认。

无可靠估计按最近一次合格估计时间计时，首次入床从确认在床时开始。长在床按连续被观察的在床时间；离床未返必须本监护会话先有在床事实，初始无人不触发。停止、停用、离床导致相关条件不再适用、输入换代时，以END而非RECOVER结束对应事件。所有规则都是工程状态，不把无可靠呼吸估计称为呼吸暂停。

0140数据：0/u64boot；8/u32monitor；12/u32enabled；16/u32active；20/u32unknown；24/u32pending；28/u32event_last；32/u32event_ack；36/u32overwrites。active与unknown可以同时置位，表示原异常锁存但当前数据未知，不能显示为正常。

0141页头32字节：0/u64boot；8/u32monitor；12/u32oldest；16/u32latest；20/u32overwrites；24/u32gap；28/u32count。传入after为上次已收到的序号，首次0；返回最多5条。gap=1明确告知历史已被覆盖，主板同时补查0140当前状态。RAM保留最近32条，复位后清空，以新boot隔离；ACK只确认接收，不清报警，不等于事件持久化。

事件32字节：0/u32seq；4/u64uptime；12/u32monitor；16/u8rule(0—7)；17/u8transition(1触发、2恢复、3数据未知、4结束、5恢复观察)；18/u16reason；20/u16value；22/u16threshold；24/u32measurement_seq；28/u32保留0。reason=0正常规则转换、1停止、2配置/重建、3源重启/控制失败、4条件不适用、5数据不可用、6输入换代。数值阈值单位×10，时间类value/threshold为0，具体阈值从配置读取。
